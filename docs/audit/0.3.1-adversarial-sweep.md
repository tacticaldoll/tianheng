# Adversarial sweep — `v0.2.3..release/0.3.1`

A defect queue, not a report: every unchecked box here is work the project still owes itself.
Each entry is sized to become **one OpenSpec change** (propose → apply → sync → PR), so this file is
the input to that lifecycle rather than a substitute for it.

## Provenance, and how much to trust an entry

Produced by two multi-agent sweeps over the whole workspace: **12 finders** (six per round, one per
subsystem, partitioned so the rounds did not overlap), each finding then put through **three
independent refutation lenses** — trace-the-code-path, is-it-a-stated-bound, and
is-it-reachable-from-adopter-input — with verifiers instructed to refute by default when uncertain.
A finding survived only if at least two of three lenses could not refute it.

**The tallies are agent verdicts, not maintainer reproductions.** Several verifiers report having
executed the trigger, but only **one** entry has been reproduced by the maintainer so far — the
`lexer.rs:367` char-literal one, marked **REPRODUCED** inline, where doing so both confirmed the
defect and corrected its description twice over. Treat every other entry as a *hypothesis with
evidence attached*: reproduce it first, annotate what the reproduction actually showed, and if it
does not reproduce, strike it from this file with a note rather than leaving it to rot.

Totals: **48 findings hunted** — 22 survived, 6 upheld by only one lens
(discarded by the ≥2 rule but recorded below), 6 refuted outright, 14 never verified
(a quota limit cut the verification tail; the finders themselves all completed).

Legend: `[3/3]` = three lenses upheld it · `[2/3]` = two upheld, one refuted · category is the
contract clause it breaks, `false-negative` being the one the core contract forbids outright.
