# The projection register

Every generated document in this repository, the reaction that holds it fresh, and the command its own
header names for regenerating it. Enumerated from tracked content by the marker each document carries, so
a document enters this table the moment it declares itself generated.

Generated by `crates/tianheng/tests/projection_register.rs`. **Do not edit by hand** — regenerate with
`BLESS=1 TIANHENG_WORKSPACE_TESTS=1 cargo test -p tianheng --test projection_register`.

## What registration in this table does not mean

**Not freshness.** Each document's own holder asserts that its content matches what the code would
produce, and duplicating that here — inside the register built to end duplication — would refute itself.
This table says a document is known, has a reaction behind its warning, and can be found.

**Not that the command works.** The regeneration command in each header is registered and never run.
Verifying it would mean re-entering the `cargo test` harness already running, or letting this reaction
write into the tree it judges. A header naming a command that regenerates nothing is invisible here, and
that is a declared observation bound rather than an oversight.

**Not that the set is complete.** Two mechanisms are recognized: a Rust call to the shared blessing rule,
and a `check_*` gate writing its projection under `BLESS`. A document generated some third way, whose
author also omitted the marker, is absent from both sides of the correspondence — a declared false
negative owned by this engine, not a limit of what it can read.
