### Requirement: The preamble describes only how to read the projection, not crate-specific law

The artifact's fixed preamble SHALL describe only how to read and use the projection and the reaction loop it serves (declare intent in code; observe only what has an observation source; react with the 0/1/2 outcomes; repair toward the declared `reason`; never weaken the law to pass; 三儀 measure, and each governance surface is named by what it does). The preamble SHALL NOT make crate-specific architectural claims; any such claim SHALL appear only in the generated projection, where it traces to a boundary that actually reacts (no open-loop prose prescription).

#### Scenario: Crate-specific law appears only in the generated projection

- **WHEN** the preamble is read
- **THEN** it describes the reaction loop and how to read the projection, and makes no crate-specific architectural claim — such claims appear only in the generated boundary projection below it

The preamble SHALL introduce **no governance name without saying what it does**. "三司 administer" named three
surfaces and gave a reader no referent for any of them, in the one file every agent loads — so they read as
three brandable things, and the question of whether one should become a crate was asked from that reading
rather than from the tree. A name whose referent is absent is worse than absent: it is loaded into context as
though it named something to be found.

**Nothing observes this**, and that is stated rather than left to be discovered. The preamble is a hand-written
constant, and deciding that a name in it lacks a referent is a judgement over prose — the instrument this
repository designed, measured three times and rejected. It is a rule an author follows, not a reaction an
author meets.
