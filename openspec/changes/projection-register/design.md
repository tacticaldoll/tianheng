## Context

Four generated documents; two mechanisms holding them fresh; one hand-written mention of each in `AGENTS.md`.
Measured on the tree:

| document | generator it names | mechanism |
| --- | --- | --- |
| `AGENTS.self-law.md` | `crates/tianheng/tests/self_governance.rs` | `assert_projection_fresh_with_preamble` |
| `docs/observation-bounds.md` | `scripts/check_bound_register.sh` | shell, `BLESS=1` |
| `docs/observation-bound-extents.md` | `crates/tianheng/tests/observation_bound_model.rs` | `assert_projection_matches` |
| `docs/gate-shape-contract.md` | `crates/tianheng/tests/gate_shape_contract.rs` | `assert_projection_matches` |

`crates/tianheng/src/testing.rs` defines the rule and holds no projection of its own, so it is not a holder.

## Goals / Non-Goals

**Goals.** Make the set of generated documents known rather than remembered. Make a reader's route to each one
checked. Keep both directions of the correspondence, since each catches a different defect.

**Non-Goals.** Freshness — each holder owns that, and a second implementation of one rule inside the register
built to stop duplication would be self-refuting. Running the regeneration commands (see D3). Governing what a
projection *contains*; that belongs to the capability whose facts it renders.

## Decisions

### D1 — The document declares itself, in bold and in its header

The enumeration is tracked Markdown carrying the marker **bolded** and **before the first `##` heading**. Measured:
4 of 4 projections satisfy both — marker at lines 4, 7, 10 and 22 against first headings at 18, 10, 50 and 29 —
and each writes it as `**Do not edit by hand**`.

Both qualifiers are corrections found reviewing this proposal, and either alone would be enough:

- A rule on the bare string would enumerate **this capability's own spec**, which quotes the marker in prose while
  stating the requirement. A register whose first act is to register the document defining it as generated would
  be a false positive in its own founding member.
- Position is the stronger of the two and is the one with a reason beyond avoiding a collision: a generated
  document warns at the **top**, because that is where a reader about to edit it looks. A warning below the first
  section heading is a warning placed where the damage has already been done.

Bold is kept as well because it is what all four already write, and because it distinguishes a document *carrying*
the warning from a document *discussing* it — which is exactly the distinction the spec's own prose needs.

This is a requirement on **authored form**, legitimate by ownership — these documents are generated by this
repository for this repository — and it is the same line `observation-bound-register` draws when it requires a
scenario heading's marker while declining to require a pinning test's name.

The alternative, deriving the surface from the holders alone, was rejected for the reason D2 gives: it cannot see a
document whose generator this reaction does not recognize, and the marker can.

### D2 — Both directions, because each catches a different defect

- **Document without a holder.** A file says "do not edit by hand" and nothing asserts its freshness. It is then
  a hand-maintained document wearing a generated document's warning — the worst of both, because a reader trusts
  it more than prose and no reaction defends it.
- **Holder without a document.** A reaction blesses a document that carries no marker, or that `AGENTS.md` never
  names. The freshness holds and no reader is told the document exists.

The second direction is why the holders are enumerated independently rather than read off the documents' own
claims. A document naming its generator is a claim by the document; the call site is the fact.

**The shell holder is recognized as a gate, not by mentioning `BLESS`.** Measured: two scripts mention it, and one
is `scripts/test_bound_register.sh` — the twin that *proves* the blessing behaves, which writes no projection of
its own. The naive recognizer therefore has a named false positive, and the fix is a shape rather than an
exclusion list: a shell holder is a `check_*` gate that writes a document under `BLESS`. A twin is not a gate, so
it falls outside without being named.

### D3 — The regeneration command is not run, and that is a declared bound

Each header names the command that regenerates it. Verifying the claim means running it, and both mechanisms
refuse:

- The Rust ones are `BLESS=1 cargo test …`. Running that from inside a test re-enters the harness currently
  running, and the repository has already paid for a nested-harness assumption once — the bound register's
  citation check was rejected twice on an unmeasured premise about `cargo test` cost before being measured at
  ~107ms. That measurement does not transfer: enumeration is not execution, and a nested `--all-features` run is
  not 107ms.
- The shell one is `BLESS=1 bash scripts/check_bound_register.sh`, which **writes** the projection. A reaction
  that mutates the tree it judges makes its own next verdict unreproducible, which is a property this repository
  requires of every gate.

So the command string is registered and not verified, and a header naming a command that regenerates nothing is
invisible. Declared as a bound, `OutOfReach`: the reaction reads the header and never evaluates it.

### D4 — A third mechanism is a declared false negative, owned by the engine

The holder enumeration knows two mechanisms by name. A document generated some third way — a `build.rs`, a
committed script output — would carry no recognized call site, and if its author also omitted the marker it is
absent from both sides of the bijection, which then holds over a surface missing a member.

This is **not** out of reach: the third mechanism's source sits in the corpus this reaction already reads. It is
seen and not reacted to, so it is an `UnderReacts` owned by the **engine** — a declared false negative, and the
count in `docs/observation-bound-extents.md` moves accordingly. Recording it as out-of-reach would be the
misclassification `observation-bound-model` exists to prevent.

### D5 — The register registers itself

Its own projection carries the marker, names its generator, and appears in its own table, for the reason
`observation-bound-model` classifies its own bounds: a register whose leading figure is a count of documents
cannot exempt the document doing the counting.

This has a consequence worth stating rather than discovering, and the tracked-content rule makes it three steps
rather than two: **bless, track, bless again.** The first blessing writes a document the enumeration cannot see,
because the enumeration reads tracked content and the new file is untracked; `git add` makes it a member; the
second blessing writes the table that includes it. A property of any self-including register over tracked content,
not a defect — but a first run stopping after one blessing would leave a projection that is stale about itself.

### D6 — Named in `AGENTS.md`'s prose, meaning outside every fenced block

The requirement is that each projection's path appears in `AGENTS.md`. Not "in a particular paragraph": the two
paragraphs carrying them today were written at different times for different reasons, and requiring a location
would be a rule about document structure rather than about a reader's route.

A mention inside a fenced code block does not count. The concern is the one the previous change was bitten by —
the Definition-of-Done membership check read a path out of a command's trailing comment — and it is live here:
`docs/observation-bounds.md` appears both in prose and in a `#` comment inside the Definition of Done fence, so a
rule counting either would accept a projection that only a gate's comment mentions.

The first draft of this decision said "a trailing comment does not count", carried over from that change without
checking that it transfers. It does not: Markdown has no `#` comment, and cutting each line at its first `#` would
truncate every heading — including `## Self-governance`, the paragraph the check most depends on. The implementable
and more honest rule is **outside every fenced block**, which says what is actually meant: prose is where a reader
is sent, a fence is where a command lives.

## Risks / Trade-offs

**The marker can be omitted, and then the document is invisible from the document side.** That is what D2's second
direction is for, and it closes the case for the two known mechanisms. D4 declares what remains.

**Four members is a small surface, and a register over four things can look like ceremony.** The answer is not the
count but the drift: the fourth member was added three days ago, and adding it required a hand edit to `AGENTS.md`
that nothing checked. A register whose cost is one reaction and one blessed document is cheaper than the sweep that
finds the missing mention later.

**It adds a false negative to the family's own count.** D4 moves the declared-false-negative figure in
`docs/observation-bound-extents.md` up by one. That is the register working as intended: the figure exists to be
moved by honesty, and a change that added a capability while leaving the figure alone would be the one to
distrust.
