## Why

The shell-comment self-governance scenario claims dependency membership cannot be copied into authored
comments, but its reaction only rejects the DSL token. A comment spelling the live allowlist without
`restrict_dependencies_to(` therefore passes while recreating the drift-prone duplicate the scenario names.

## What Changes

- Derive the unique shell dependency boundary and its allowed members from `tianheng_constitution()`.
- Reject a contiguous authored line-comment block that contains every live allowlist member, even when it
  omits the DSL token or spans lines.
- Keep single-member architectural discussion and executable DSL calls outside the refusal.
- Add mutation evidence for the copied-members form and retain the existing shell metadata-edge fixture.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `self-law-projection`: Make the existing no-copied-members requirement react to the live allowlist rather
  than only to the declaration token.

## Impact

Only Tianheng's repository-only self-governance test and the synced self-law-projection spec are affected.
The accepted constitution, generated projection, public APIs, manifests, versions, and dependencies remain
unchanged.
